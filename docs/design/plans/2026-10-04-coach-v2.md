# Coach v2 — plan d'implémentation

> Steps use checkbox (`- [ ]`) syntax for tracking. Une tranche = une livraison vérifiable ;
> les tranches 2 à 5 sont détaillées au moment de les ouvrir, sur le code tel qu'il sera alors.

**Goal :** faire lire au coach l'effort, l'intention, l'échelle, le contexte et le volume, sans
quitter le moteur pur et déterministe de `src/lib/coach/`.

**Architecture :** chaque règle est une fonction pure de `lib/coach` (ou de `lib/loadIncrement`),
alimentée par des champs que l'app enregistre déjà. Un banc de rejeu, pur lui aussi, rejoue une
sauvegarde séance par séance pour comparer le moteur avant / après chaque tranche.

**Tech Stack :** TypeScript strict, Vitest. Aucune dépendance nouvelle.

**Spec :** `docs/design/specs/2026-10-04-coach-v2-design.md`

## Global Constraints

- Code et noms en **anglais**, interface en **français** dans `src/i18n/fr.ts`.
- `lib/coach` reste pur : ni Dexie, ni `Date.now()`, ni réseau.
- **Aucune sauvegarde réelle dans le dépôt.** Les cas utiles deviennent des fixtures de quelques
  séries, écrites à la main.
- TDD : chaque test est vu rouge avant le code qui le fait passer.
- Aucune assertion existante modifiée sans que le commit dise pourquoi elle décrivait un défaut.
- À la fin de chaque tranche : `npm run typecheck`, `npm run lint`, `npm run test:run`,
  `npm run build` verts, et rejeu de la sauvegarde avant / après consigné dans `PROGRESS.md`.

### Tranche 0 — le banc de rejeu

**Files :**

- Create : `src/lib/coach/backupLines.ts` (+ test), `src/lib/coach/replay.ts` (+ test),
  `src/lib/coach/replay.cli.test.ts`
- Modify : `package.json` (script `coach:replay`), `.gitignore`

**Interfaces :**

- `coachLinesFromBackup(backup: BackupFile): CoachExerciseLine[]` — séances `completed` et vivantes,
  séries validées horodatées ; mesure et équipement lus sur l'exercice, sinon sur l'instantané de
  la ligne, comme `loadCoachHistoryLines`.
- `replayCoach(lines, options?): ReplayStep[]` — pour chaque exercice et chaque séance, dans
  l'ordre, `evaluatePerformance(séance, séances antérieures)` ; un pas porte tous les signaux, celui
  qui serait affiché (`pickSignals`) et les actions autorisées.
- `formatReplay(steps, names): string` — une ligne par pas, triées par exercice puis par date.

- [ ] Tests de `coachLinesFromBackup` : séance supprimée, séance active, série non validée,
      série sans horodatage, exercice absent (repli sur l'instantané).
- [ ] Tests de `replayCoach` : une séance n'est jamais jugée avec une séance postérieure ; deux
      exercices restent indépendants.
- [ ] `replay.cli.test.ts`, sauté sans `COACH_REPLAY_BACKUP` ; imprime le rejeu (ou l'écrit dans
      `COACH_REPLAY_OUT`). Script : `COACH_REPLAY_BACKUP=… npm run coach:replay`.
- [ ] `.gitignore` : `fittrack-sauvegarde-*.json`, `coach-replay*.txt`.

### Tranche 1 — R2 (série à l'échec) et R3.1 (pas déduit)

**Files :**

- Modify : `src/lib/coach/evaluate.ts` (+ test), `src/lib/loadIncrement.ts` (+ test),
  `src/features/workout/coachCopy.ts` (+ test), `src/i18n/fr.ts`

**Interfaces :**

- `judgedSets(line)` : `progressionSets` sans les séries `failure`. Lue par la partition plafond /
  fourchette, `floorMiss`, `intraSessionDropSignal` et `isCappedSession`. Le 1RM, la charge du
  haut et le record de répétitions continuent de lire les séries à l'échec.
- Évidence `failure_reps_over_ceiling` sur le signal de partition quand une série à l'échec, à la
  charge de référence, dépasse le plafond (décision Q5 : information).
- `inferLoadIncrementKg(loads: readonly number[]): number | undefined` : plus petit écart entre
  charges distinctes consécutives, s'il apparaît au moins deux fois et vaut au moins 0,5 kg.
- `coachIncrementKg(line, history)` : réglage de l'exercice → pas déduit s'il est plus fin que la
  table → table par équipement. Évidence `inferred_increment_kg` quand le pas déduit sert.

- [ ] Tests R2 (spec § 10) : `12 @8,5 · F 8 @9,5` → pas de baisse ; `5 × 12 · F 5 × 10` deux fois sur
      12–15 → pas de `range_missed` ; séance faite seulement de séries à l'échec → aucun signal de
      fourchette ; série à l'échec à 18 sur 12–15 → évidence `failure_reps_over_ceiling = 3`.
- [ ] Tests `inferLoadIncrementKg` : 7,5 / 10 / 12,5 → 2,5 ; 3,5 / 5 / 6,125 → rien (un seul écart
      minimal) ; écart minimal 0,25 → rien ; charges identiques → rien.
- [ ] Tests moteur : machine chargée à 10 / 12,5 / 15 puis plafond à 15 → 17,5 et évidence ;
      réglage explicite de 5 sur l'exercice → il l'emporte sur le pas déduit.
- [ ] `coachCopy` : le pas déduit et la marge de la série à l'échec s'ajoutent au message, en
      français, sans changer les phrases existantes.
- [ ] Rejeu avant / après sur la sauvegarde, différences relues une à une.

### Tranche 2 — R1 (effort)

jugées, défini si la moitié en porte un) ; plafond à l'arraché (≥ 9,5 → pas d'`increase_load`,
drapeau `ceiling_grinding`) ; code `consolidating` ; plateau levé par un effort en baisse, drapeau
`at_failure`. Nouveau code dans `CoachSignalCode`, `coachCopy`, `fr.ts`.

### Tranche 3 — R4 (même contrat) et R5 (retour de pause)

Historique de séance à séance restreint au même `(targetReps, targetRepsMax)` ; écart ≥ 14 jours →
signal `returning`, pas d'escalade, fenêtres remises à zéro.

### Tranche 4 — R3.2 (pas relatif)

Pas > 10 % de la charge → `increase_reps` jusqu'à `targetRepsMax + 3` avant `increase_load` ;
évidence `relative_step_pct`. À valider en salle avant la tranche suivante.
