# Coach v2 — plan d'implémentation

> Steps use checkbox (`- [ ]`) syntax for tracking. Une tranche = une livraison vérifiable ;
> les tranches 2 à 5 sont détaillées au moment de les ouvrir, sur le code tel qu'il sera alors.

**Goal :** faire lire au coach l'effort, l'intention, l'échelle, le contexte et le volume, sans
quitter le moteur pur et déterministe de `src/lib/coach/`.

**Architecture :** chaque règle est une fonction pure de `lib/coach` (ou de `lib/loadIncrement`),
alimentée par des champs que l'app enregistre déjà. Un banc de rejeu, pur lui aussi, rejoue une
sauvegarde séance par séance pour comparer le moteur avant / après chaque tranche.

**Tech Stack :** TypeScript strict, Vitest. Aucune dépendance nouvelle.

**Spec :** `docs/design/specs/2026-10-04-coach-v2-design.md`

## Global Constraints

- Code et noms en **anglais**, interface en **français** dans `src/i18n/fr.ts`.
- `lib/coach` reste pur : ni Dexie, ni `Date.now()`, ni réseau.
- **Aucune sauvegarde réelle dans le dépôt.** Les cas utiles deviennent des fixtures de quelques
  séries, écrites à la main.
- TDD : chaque test est vu rouge avant le code qui le fait passer.
- Aucune assertion existante modifiée sans que le commit dise pourquoi elle décrivait un défaut.
- À la fin de chaque tranche : `npm run typecheck`, `npm run lint`, `npm run test:run`,
  `npm run build` verts, et rejeu de la sauvegarde avant / après consigné dans `PROGRESS.md`.

### Tranche 3 — R4 (même contrat) et R5 (retour de pause) — faite

`contractKey` (paires de cibles des séries de travail) restreint `range_missed`, le plateau et la
consolidation aux séances du même contrat ; le pas déduit lit toujours tout. `sinceLatestReturn` :
écart ≥ 14 jours avec la séance précédente de l'exercice, quelle qu'en soit la fourchette → signal
`returning` (sévérité 45), plafond sans charge, ni `increase_load` ni `add_set`, fenêtres coupées à
la reprise. Récap vocal : un plafond arraché ou une reprise ne sont plus lus comme une hausse, et
« plan inchangé » n'est dit que s'il n'y a rien d'autre.

- [x] Tests R4 et R5 (spec § 10), vus rouges sur le moteur de la tranche 2.
- [x] Carte, récap vocal, liste des codes de la validation des sauvegardes.
- [x] Rejeu avant / après relu.

### Tranche 4 — R3.2 (répétitions pour absorber le cran) — faite

Première version (10 % de saut maximal, 3 répétitions au-delà de la fourchette) écartée par
l'utilisateur avant d'être codée : le cran est celui du matériel, ce sont les répétitions qui
s'adaptent. `repsToAbsorbStep` (inverse d'Epley, arrondi au plus proche) dans `lib/oneRepMax` ;
`repsNeededForStep` dans le moteur, charges seulement (`weightRole: 'load'`). Tant que toutes les
séries n'y sont pas : plafond sans charge proposée, évidences `step_needs_reps`, `next_step_kg`,
`target_reps` ; seule `increase_reps` autorisée. Carte `coach.stepNeedsReps`, récap vocal sur
« progrès ».

- [x] Sept tests existants dont le sujet était ailleurs (arrondi, pas déduit, fenêtre, écran de
