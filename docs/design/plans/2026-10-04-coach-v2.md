# Coach v2 — plan d'implémentation

> Steps use checkbox (`- [ ]`) syntax for tracking. Une tranche = une livraison vérifiable ;
> les tranches 2 à 5 sont détaillées au moment de les ouvrir, sur le code tel qu'il sera alors.

**Goal :** faire lire au coach l'effort, l'intention, l'échelle, le contexte et le volume, sans
quitter le moteur pur et déterministe de `src/lib/coach/`.

**Architecture :** chaque règle est une fonction pure de `lib/coach` (ou de `lib/loadIncrement`),
alimentée par des champs que l'app enregistre déjà. Un banc de rejeu, pur lui aussi, rejoue une
sauvegarde séance par séance pour comparer le moteur avant / après chaque tranche.

**Tech Stack :** TypeScript strict, Vitest. Aucune dépendance nouvelle.

**Spec :** `docs/design/specs/2026-10-04-coach-v2-design.md`

## Global Constraints

- Code et noms en **anglais**, interface en **français** dans `src/i18n/fr.ts`.
- `lib/coach` reste pur : ni Dexie, ni `Date.now()`, ni réseau.
- **Aucune sauvegarde réelle dans le dépôt.** Les cas utiles deviennent des fixtures de quelques
  séries, écrites à la main.
- TDD : chaque test est vu rouge avant le code qui le fait passer.
- Aucune assertion existante modifiée sans que le commit dise pourquoi elle décrivait un défaut.
- À la fin de chaque tranche : `npm run typecheck`, `npm run lint`, `npm run test:run`,
  `npm run build` verts, et rejeu de la sauvegarde avant / après consigné dans `PROGRESS.md`.

### Tranche 5 — R6 (volume par muscle) — faite

**Décisions d'ouverture** (2026-10-14, en autonomie ; amendement daté dans la spec, R6). Chacune est
une **politique**, pas une vérité (invariant 4) :

- **Rien n'est journalisé.** `volume_low` est un constat de semaine, sans suite à suivre ni à refuser :
  il ne passe pas par `coachRecommendations`, donc aucun `exerciseId` facultatif et **aucune version de
  schéma**. Le plafond, lui, ne crée pas de signal : il retire `add_set` des actions permises.
- **Le plafond ne parle que quand il change quelque chose.** `add_set` n'est *choisi* qu'en phase de
  surcharge d'un bloc (`selectProgramAction`). La note « pas de série en plus » n'apparaît donc que si
  le plafond a retiré une action que la phase aurait choisie — pas sur chaque plafond d'un pratiquant
  régulier, dont le volume est par définition à son maximum.
- **Semaines complètes pour la référence et le plancher, 7 jours glissants pour la décision.** Lundi
  à lundi, en jour local (`startOfLocalWeek`) : six semaines avant la semaine en cours. La semaine en
  cours est incomplète, elle ne juge personne ; elle ne sert que de volume courant au plafond.
- **Une médiane de semaines travaillées.** Six semaines dont deux de repos feraient une médiane de 0 et
  un plancher absurde. L'écran montre ce que la personne fait **les semaines où elle travaille le muscle**.
- **Une semaine sans séance n'est pas un volume bas.** `volume_low` exige une séance, tous muscles
  confondus, dans chacune des deux semaines : deux semaines de vacances ne font pas dix alertes.
- **Un muscle sans région n'a pas de bornes.** `cardio`, `full_body`, `other` : un zéro n'y dit rien
  (cf. `MUSCLE_SCOPE`). Seize muscles, comme l'écran « séries par muscle ».
